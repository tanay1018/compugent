Why not just run the agent every time

Because an LLM in the loop makes every run a fresh negotiation with the UI. It is slow, it costs money per invocation, and — the part that matters for back-office work — it is not repeatable. The same request can take a different path on Tuesday than it did on Monday, and you cannot audit or approve a process that reinvents itself each time.

So the model is used for the thing it is genuinely good at: figuring out how the software works, once, by looking at it. What it learns is compiled into an artifact — parameters, steps, targets, waypoints, outputs, failure classifications — and from then on the artifact is what runs.

Discovery · minutes, costs tokens

A model drives the surface, one action per step, re-reading the screen after each. Produces a trace.

Replay · ~11s, costs nothing

Resolve target, act, verify waypoint, read outputs. Deterministic, auditable, no network call to a model.

The hard part is naming things

Legacy business software does not label its inputs. The accessibility tree hands you a textbox with no accessible name at all — nothing to target it by. This is not an edge case; it is the normal condition of the software people actually use at work.

So targeting is built around anchor relations: the thing next to it is its identity. A field in the same row as the label "ISIN". A control preceded by the text "Transfer amount". This makes the system work on surfaces that were never designed to be automated — and it is surface-agnostic, because the same relations exist in macOS AX and Windows UIA.

extract cell inSameRowAs "ISIN"           -> isin
extract cell inSameRowAs "Industry"       -> industry
extract cell inSameRowAs "Headquarters"   -> headquarters

Those three lines are from a live Wikipedia article. An infobox cell has no name of its own — the label in the neighbouring cell is the only thing that identifies it.

Determinism is not generalisation

A capability that works only for the value it was recorded on is a recording, not a capability — and repetition cannot tell the difference, because the recorded case passes identically every time. Proving it generalises means replaying it against values it has never seen.

The gate earning its place

A second capability read the temperature off a government weather site. It anchored that value to precededBy "Overcast" — the current conditions text, which is data wearing the shape of a label. The compiler could not know: it sees one trace, and on that trace the anchor was right there.

$ verify weather.readForecastByZip --case "zipCode=10001" --case "zipCode=90210"

  pass  recorded  {"currentTemperatureF":78,...}
  fail  unseen    output_missing: currentTemperatureF at precededBy "Overcast"

  PINNED — works on the recorded value and fails on values it has not seen.

Beverly Hills was not overcast. Twenty-four hours later New York read "Fair", and the capability failed on its own recorded ZIP too. It was never promoted: the model produced it, the compiler accepted it, and the gate refused it. A single green replay on the day of recording would have shipped it.

An anchor must be a label, not a value. inSameRowAs "ISIN" holds because every company article has an ISIN row. precededBy "Overcast" holds until the weather changes.

A human can take the wheel

Automation that cannot be interrupted is not deployable in an environment where a person is accountable for the outcome. Control is a single token with no shared state — either the agent holds it or the operator does, and the handover is atomic at a step boundary.

When the operator hands it back, the agent does not resume at the step it was on. It re-reads the screen and re-locates itself in the plan, because the person may have done three steps of the work themselves, or navigated somewhere else entirely. The plan is a map, not a program counter.

What it does not do

Measured, not suspected — each is a real page it handles badly.

Bot wallsA major retailer returns 6 accessibility nodes — the CDN block page. Nothing is rendered to perceive.
Values with no labelSome pages put nothing label-shaped beside the number. No anchor choice fixes a page with no anchor.
Definition listsA <dl> layout presents neither a table row nor preceding label text. Needs a third relation kind.
Prompt cachingNot yet reusing the prompt prefix across steps. Pure cost, no correctness impact.

It works on pages whose structure carries meaning. It degrades on pages that are visually structured but semantically flat, and it does not work where a CDN decides it shouldn't.
