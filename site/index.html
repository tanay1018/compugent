Why not just run the agent every time

Running an LLM on every invocation is slow, costs money each time, and is not repeatable: the same request can take a different path from one day to the next. For back-office work, a process that changes each run cannot be audited or approved.

Instead, the model is used once to work out how the software behaves. The run compiles into an artifact (parameters, steps, targets, waypoints, outputs, outcome classifications), and from then on the artifact is what runs.

Discovery · minutes, costs tokens

A model drives the surface one action at a time, re-reading the screen after each. Produces a trace.

Replay · ~11 s, no model calls

Resolve target, act, verify waypoint, read outputs. Deterministic and auditable.

Determinism is not generalisation

Repeating the recorded input only shows that a capability is deterministic. To show it generalises, it has to be replayed against inputs it was not recorded with.

A capability that did not generalise

A second capability read the temperature off a government weather site. It anchored that value to precededBy "Overcast", the current-conditions text, which is data rather than a label. From a single trace the compiler cannot tell the difference.

$ verify weather.readForecastByZip --case "zipCode=10001" --case "zipCode=90210"

  pass  recorded  {"currentTemperatureF":78,…}
  fail  unseen    output_missing: currentTemperatureF at precededBy "Overcast"

  PINNED — works on the recorded value and fails on values it has not seen.

Beverly Hills was not overcast. A day later New York read “Fair”, and the capability failed on its own recorded ZIP too. Verify kept it from being approved.

An anchor must be a label, not a value. inSameRowAs "ISIN" holds because every company article has an ISIN row. precededBy "Overcast" holds until the weather changes.

Run the whole thing yourself

The desktop app includes the full system: give it a URL and a task, watch the agent work, take control at any point, save the run as a capability, and replay it later without a model.

Your API key is stored in the app’s local settings directory and is only sent to the AI Gateway. There is no backend server.

Download for macOS Source on GitHub
  1. Install and open it. The first launch downloads a private Chromium build for the agent to drive.
  2. Paste an AI Gateway key into Settings. Discovery needs it; replay does not.
  3. Give it a URL and a task in plain English, and watch. Take control at any step; hand it back when you are done.
  4. Save the run as a capability, then replay it with different inputs. Replay does not call a model.

Builds are not yet signed or notarized. On first launch macOS will block the app: open System Settings → Privacy & Security and click Open Anyway. Running from source is documented in the repository.

What it does not do

Each row is a real page it handles badly.

limitwhat happens
Bot wallsA major retailer returns 6 accessibility nodes: the CDN block page. There is nothing to perceive.
Values with no labelSome pages put nothing label-like beside the value, so there is no anchor to record.
Definition listsA <dl> presents neither a table row nor preceding label text. Needs a third relation kind.
Prompt cachingThe prompt prefix is not cached across steps. Affects cost only.

It works on pages whose structure carries meaning. It degrades on pages that are visually structured but semantically flat, and does not work behind bot protection.
